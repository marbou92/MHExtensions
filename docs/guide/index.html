Guide

Everything about using, publishing and extending MHExtensions.

Adding the repository

Visit the Add store page and either use the deep link or copy the repository URL: 

https://raw.githubusercontent.com/marbou92/MHRepo/main/repo.json

In Mihon: More → Settings → Browse → Extension repositories → Add repository, paste the URL and confirm. Then open Browse → Extensions and refresh.

Installing extensions

  1. Open Browse → Extensions. Sources are grouped by language (use the Languages filter to pick what you read).
  2. Tap Install next to an extension. On the first install the app asks you to trust the repo's signing key — accept it once.
  3. Enable the individual sources under Browse → Sources (multi-language extensions publish one source per language).

Updating extensions

The app checks the repo index automatically — when an extension is bumped and republished to MHRepo, the update shows up like a normal app update. Nothing to do by hand.

Troubleshooting

  • Empty extension list / "Outdated app" — your app is no longer compatible. MHExtensions only supports Mihon, TachiyomiSY and Komikku; update your app.
  • Cloudflare check inside the app — some sources (Comix, Kagane, MangaGo, MangaDot, ManhuaRMTL…) ride a WebView-based Cloudflare solver. If a challenge appears, complete it once in the WebView window; the clearance is reused afterwards.
  • MKissa shows no chapter images — that's intentional: the site's anti-bot token explicitly blocks scraping. Browse, search, details and the chapter list work; open the chapter on the site for now.
  • 403 / invalid token errors — the source site changed its protection layer. File an issue.

Publishing extensions

Signing secrets live in Settings → Secrets and variables → Actions:

SecretPurpose
SIGNING_KEYBase64-encoded .jks keystore file
KEY_STORE_PASSWORDKeystore password
ALIASKey alias name
KEY_PASSWORDKey password
REPO_PATGitHub PAT with write access to marbou92/MHRepo
SIGNING_FINGERPRINT_MANUALSHA-256 fingerprint of the signing key (cleanup mode)

Release flow

  1. Bump versionCode in the extension's build.gradle.kts.
  2. Commit and push to main.
  3. Actions → Release & Publish → Run workflow, select publish, run.

The workflow builds signed release APKs for every extension in settings.gradle.kts, computes the signing-key fingerprint, and publishes APKs, icons and the protobuf index (index.pb) to MHRepo, then purges the jsDelivr CDN cache.

Cleaning up orphaned extensions

If an extension is renamed or moved, its old entry stays in MHRepo's index. Run Release & Publish with cleanup-dry-run to preview deletions, then cleanup to apply.

Local builds

Anything built locally (e.g. a fix delivery) can be installed directly — the debug/release key matches what CI signs with, so local APKs install over published ones.

Adding a new extension

  1. Create src/<lang>/<name>/ with the extension source.
  2. Add loadIndividualExtension("<lang>", "<name>") to settings.gradle.kts.
  3. Add the launcher icon at src/<lang>/<name>/res/mipmap-xhdpi/ic_launcher.png.
  4. Commit, push, run the publish workflow.

The website catalog picks it up automatically — the Update website index workflow regenerates docs/index.json and the icon copies whenever src/ changes.

The website

This site lives in docs/ — plain HTML/CSS/JS, zero build step, served by GitHub Pages (Settings → Pages → Deploy from a branch → main → /docs). Pages use clean directory URLs (/extensions/, /add-repo/, /guide/) — the old *.html links redirect automatically. The style mirrors keiyoushi.github.io.

Extension notes

  • Comix — signed+encrypted JSON API. The site's VM-protected signer means every /api/v1 call runs through a WebView bridge that boots the site's own chunk graph and lets the site sign/decrypt in-JS; frozen native constants stay as the fast path. Cloudflare bypass, tile descrambling, 10 settings.
  • ManhuaRMTL — Madara theme with custom MRM selectors; Popular/Latest dedup via the archive endpoint; OCR text overlay burned onto raws in Arabic + 10 languages, toggleable; NSFW filter; full filter sheet.
  • Kagane — Komga-fork /api/v2 with short-lived integrity tokens for chapter manifests; transparent page-token refresh; data saver.
  • Atsumaru — home2 browse endpoints + Typesense search; full filter set.
  • MKissa — GraphQL persisted queries; browse/search/details only (anti-bot images).
  • MangaDot — one source per content language (100+); Cloudflare solver.
  • MangaBall — all-languages source.
  • Swarm — swarm sites.
  • XComic — reconciles the rendered Sources grid with the page state so hidden groups are fetched too; real scanlator badge naming; per-number dedupe across languages.
  • WeebCentral — English source.
  • MangaTaro — WordPress manga/v1 JSON API with the theme's double-encoded filters and MD5 chapter tokens; curated TriState genre list.
  • Toonz — Next.js + JSON endpoints; JSON-LD details; browse section setting.
  • MangaGo — classic HTML browse/search; reader images harvested from the window-attached WebView; route-level CF solving.
  • MangaFire — one source per content language (en, fr, es, es-la, pt, pt-br, ja); vrf-protected API signed offline by the site's own polyfill chunk running in a WebView; full filter sheet; smart description.
